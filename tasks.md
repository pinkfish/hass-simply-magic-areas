### Machine Learning & Multi-Sensor Signal Processing
- [x] **Dual-Stage Shower Classifier & Trajectory Moisture Evacuation Modeling**: Formulated architecture in [designs/ml_fusion_mmwave_and_environmental_design.md](designs/ml_fusion_mmwave_and_environmental_design.md) and implemented [`ShowerClassifier`](custom_components/simply_magic_areas/ml/shower_predictor.py) and [`MoistureEvacuationModel`](custom_components/simply_magic_areas/ml/shower_predictor.py). Multi-sensor logistic differential classifier integrates $dRH/dt$, $d^2RH/dt^2$, thermal flux $dT/dt$, localized meta differential $\Delta H_{meta}$, and door contact states to reject false positive ventilation triggers from broad atmospheric weather fronts and ambient room temperature swings. Dynamic exponential drying curve regression fits air exchange rate $k$ ($\ln(H(t) - H_{base}) = \ln(\Delta H_{peak}) - kt$) during downward drying slopes to project exact optimal shutoff timestamps ($t_{dry}$), eliminating stationary derivative deadband flatlining. Exposes `shower_probability`, `drying_rate_k`, and `estimated_dry_ts` entity attributes on `AreaFanGroup`. Fully verified with unit and integration tests across 94 passing tests.
- [x] **100% Local Online Bayesian Lighting Preference Learner (Zero-Cloud Personalization)**: Formulated mathematical model in [designs/ml_fusion_mmwave_and_environmental_design.md](designs/ml_fusion_mmwave_and_environmental_design.md) and implemented [`OnlineBayesianLightingLearner`](custom_components/simply_magic_areas/ml/lighting_learner.py). Operates completely on-device without cloud connectivity using pure Python matrix/vector Recursive Least Squares (RLS) and Sherman-Morrison rank-1 Bayesian Ridge Regression updates ($\mathcal{O}(d^2)$ execution $< 1\mu\text{s}$). Captures real-time user manual dimmer and slider adjustments on `AreaLightGroup` to continuously learn individual lux-to-brightness preferences across solar elevations and substate profiles. Automatically preserves daylight cutoff invariants, smoothly blends prior heuristics with learned preferences, and persists state across restarts in local JSON storage (`.storage/simply_magic_areas_lighting_ml_<area>`). Exposes `ml_adaptive_lighting_active`, `ml_preference_samples`, `ml_confidence`, and `ml_predicted_brightness` attributes. Validated with dedicated tests in [test_ml_lighting_and_fan.py](custom_components/simply_magic_areas/tests/test_ml_lighting_and_fan.py) and passing full test suite.
- [x] **mmWave Radar Fan vs. Human False-Presence Discrimination & Multi-Signal Sensor Element Evaluation**: Formulated physical Doppler and multi-target spatial model in [designs/ml_fusion_mmwave_and_environmental_design.md](designs/ml_fusion_mmwave_and_environmental_design.md) and implemented [`MMWaveFanFilter`](custom_components/simply_magic_areas/ml/mmwave_filter.py). Solved mmWave radar ghosting (continuous false occupancy caused by rotating ceiling, desk, and exhaust fans) by combining: (1) Actuator-Radar Causal Coupling directly tracking `AreaFanGroup` operational states; (2) Range Gate & Target Distance Spatial Filtering ($1.8\text{m} \le \text{dist} \le 3.5\text{m}$) and rolling variance mechanical reflection detector ($\sigma^2 < 0.02$); (3) Universal binary presence sensor dwell filtering; and (4) **Multi-Signal Sensor Element Evaluation**: When a radar sensor detects the fan, the integration bypasses the corrupted primary occupancy sensor and inspects secondary signals exposed on the device (macro-motion energy $\ge 20$, multi-target tracking outside the fan zone $[1.8\text{m}, 3.5\text{m}]$, unmasked range gates 0, 1, 5–8 energy $\ge 20$, and companion motion binary sensors) to determine if a human is present in the room. If secondary elements confirm human presence, the room remains occupied and the sensor is tracked in `radar_fan_override_sensors`; if only the fan is spinning, the sensor is silenced into `filtered_fan_sensors`; and if the sensor is a dumb binary sensor exposing no secondary signals, it falls back to dwell filtering. Fully validated with dedicated tests in [test_ml_lighting_and_fan.py](custom_components/simply_magic_areas/tests/test_ml_lighting_and_fan.py) across 95 passing tests.

- [x] **Exterior Nighttime Lighting, Motion Clock Reactivity & Resident Arrival Control**: Formulated architectural, state-machine, and mathematical models in [designs/exterior_lighting_control_design.md](designs/exterior_lighting_control_design.md) and implemented in [`AreaLightGroup`](custom_components/simply_magic_areas/light.py). ### Ventilation & Climate
- [x] **Autonomous Historical Humidity & Adaptive Shower Signature Learning**: Formulated thermodynamic and mathematical models in [designs/adaptive_humidity_shower_design.md](designs/adaptive_humidity_shower_design.md). Replaced hardcoded static boundaries with room-specific empirical learning (`CONF_LEARN_SHOWER_HUMIDITY`). Continuously tracks ambient baseline humidity ($H_{base}$) during idle periods ($|dRH/dt| < \text{trend\_up\_cutoff}$ and $RH \le H_{base} + 5\%$) using EMA ($\alpha=0.05$), enabling zero-config standalone delta derivation ($\Delta H = RH_{room} - H_{base}$) without requiring an external reference sensor. Extracts peak rise rate ($(dRH/dt)_{peak}$) and peak delta ($\Delta H_{peak}$) across shower events to dynamically scale trigger thresholds ($\Delta H_{trigger}$, $Trend_{trigger}$) and recovery shutoff target ($\Delta H_{shutoff}$). Built-in noise-floor guard rejects ambient jitter while absolute ceiling guard ($\ge 80\%$) guarantees mold protection. Validated across integration test suite with 14/14 passing tests in [test_fan.py](custom_components/simply_magic_areas/tests/test_fan.py) and 68/68 total integration suite tests.
- [x] **Bathroom Shower Humidity Dynamics & Fan Control**: Conducted thermodynamic and empirical rate-of-change analysis in [designs/bathroom_humidity_fan_design.md](designs/bathroom_humidity_fan_design.md). Solved legacy premature shutoff on negative drying slopes ($dRH/dt < 0$), eliminated AND-gate trigger deadlocks, implemented zero-config reference humidity fallback (Interior meta-area and neighboring interior areas), and established dual-trigger activation (rapid $dRH/dt$ rise OR sustained $\Delta RH$ differential) with dedicated integration test suite in [test_fan.py](custom_components/simply_magic_areas/tests/test_fan.py).
- [x] **Acoustic Fan Suppression in Sleep Mode**: Implemented `CONF_FAN_SUPPRESS_IN_SLEEP` in [fan.py](custom_components/simply_magic_areas/fan.py), [config_flow.py](custom_components/simply_magic_areas/config_flow.py), and [const.py](custom_components/simply_magic_areas/const.py). In en-suite bathrooms, loud exhaust fans are suppressed during `extended` mode when sleep mode is active (either locally or in a configured reference/sleep entity), shuts off running extended fans if sleep activates dynamically, re-engages fans if sleep ends while still extended, and safely allows elevated differential humidity (`humidity_on`) to override sleep suppression for moisture control.
- [x] **Bathroom vs. Toilet Ventilation Differentiation (`CONF_FAN_RUN_IN_EXTENDED`)**: Differentiated exhaust fan automation between bathrooms with a shower and toilets without a shower in [fan.py](custom_components/simply_magic_areas/fan.py) and [const.py](custom_components/simply_magic_areas/const.py). In toilets / powder rooms without humidity tracking, fans run automatically during the `extended` phase for `extended_timeout` to exhaust odors. In bathrooms with active shower humidity tracking, the fan does not automatically turn on in `extended` mode during routine non-shower visits (e.g. handwashing, teeth brushing) and only turns on when humidity changes (`humidity_on: true`), running continuously until moisture returns to baseline. Supports explicit override via `CONF_FAN_RUN_IN_EXTENDED`. Validated with dedicated regression test in [test_fan.py](custom_components/simply_magic_areas/tests/test_fan.py).
